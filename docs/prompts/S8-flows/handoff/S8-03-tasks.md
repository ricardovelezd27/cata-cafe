## 6. Risks

1. **Shared-Wi-Fi lockout** of the magic-link IP bucket (wrong-ref #4). Highest operational risk; constants are lead-owned.
2. **Preview/dev login breakage** from forcing `siteOrigin()` (wrong-ref #3).
3. **Dev IP absent**: if the helper falls back to a constant key, local dev locks itself out (Fact 9).
4. **Opaque digests**: converting the five throwing senders is a breaking client change; missing a caller (`AddToGroupButton`, `MemberList`, `AddByEmailForm`, `NewSessionForm`, `NotifyGroupPanel`) leaves a swallowed error. `tsc` catches union changes; add the scan in T23.
5. **Registered-only breaking a hidden guest path**: only candidate is `joinCoffeeViaToken` (handled) and any server page that calls a guarded action on behalf of a guest (none found; grep of component imports shows the group/coffee actions are used only from `/app/groups`, `/app/coffees`, `/app/sessions/new`, all proxy-gated). QR-guest smoke in T23 is the proof; `createGuestJoin` path uses `joinViaToken` + `completeGuestOnboarding` (kept).
6. **Race in `reserveEmailBudget`** (count-then-insert is not atomic; concurrent clicks can overshoot). Lead to decide transaction/advisory lock vs accepting small overshoot.
7. **Migration ordering**: deploying code before `migrate deploy` makes every group email path 500 (Prisma selects new tables/column `clientKey` on `TastingGroup` reads); runbook must say migrate first (like §9). `TastingGroup.clientKey` is selected implicitly by every `tastingGroup` query using the default select.
8. **Parallel-spec conflicts**: `sessions.ts` (S8-01: `upsertEvaluation`, `removeSessionSample`), `community.ts` (S8-01: `submitAllEvaluations`, `joinViaToken`, deletion of `submitSampleEvaluation`/`submitEvaluation`), `coffees.ts` (S8-02: `duplicateCoffee`). Guard swaps are one-line; T7/T8 are the only multi-line edits in those files and sit in `validateSessionInput` / `createCoffee`/`updateCoffee`.
9. **Certification whitelist** may reject legacy coffee data on update (wrong-ref #10).
10. **Unverified**: Resend idempotency/limit behaviour; Vercel XFF semantics; whether Prisma error text in the `e.message` warns can contain addresses; `CoffeeForm` handling of unknown error strings; exact line numbers of `composerT` in `groups/[id]/page.tsx`; production Supabase anonymous-sign-in/email rate limits (audit "Not verified").
