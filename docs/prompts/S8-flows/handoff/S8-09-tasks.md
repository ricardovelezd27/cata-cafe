3. FACTS FOR THE ARCHITECT
1. S8-05 is unbuilt, so the `closed` outcome and `closed_unsent` status do not exist. Today syncEvaluation returns "discarded" for a closed session and the client marks it synced, silently dropping the draft. Two designs: (a) S8-09 defines closed/closed_unsent itself, which must be reconciled with S8-05; (b) keep the "discarded" mapping until S8-05 lands. Recommend (a), since the status enum is T1 anyway.
2. Adding new statuses to syncEvaluation breaks service-worker-cached old bundles that expect synced|conflict|discarded. Two designs: (a) widen the return type and accept a stale-bundle window; (b) add new action names (syncEvaluationV2, replay*) and leave the old one untouched. Recommend (b).
3. Spec step 6 is infeasible as written. confirmGuestClaim is a `<form action>` that ends in redirect() (app/[locale]/auth/claim/page.tsx:98; app/actions/guestClaim.ts:73), so the client never runs code after success. Two designs: (a) store {anonId} in localStorage at startGuestClaim and rekey on the next app mount once the signed-in id differs; (b) rely only on the pre-claim guard. Rekey must also rename the cata_props_ key and rewrite blob.userId.
4. requireSampleMember throws not_found_or_forbidden for both a deleted sample and a non-member, so "gone" cannot be told from forbidden. Map both to orphaned. Catch only that message and let the rest propagate as retryable.
5. upsertPhysical/upsertExtrinsic are owner-only (requireSampleOwner), so replay classification must use the owner variant. Today they throw session_closed and retry 3x (the S8-01 handoff already notes this).
6. useOfflineSync is instantiated in both CupClient and SessionSyncStatus (results). Two instances can replay concurrently, because syncingRef is per instance. Add a module-level lock in T4.
7. The Evaluation model has no lastClientWriteAt. Two designs for F-offline-2: (a) client-only ifUpdatedAt in T2, no migration, which closes the common race; (b) T9 migration. Recommend (a) now and (b) only if wanted; the trigger and scoring are untouched either way.
8. S8-03 already carries a migration, and README allows one per prompt, so T9 is a separate migration. Spec line refs hold: store.ts:188-192, useOfflineSync.ts:91-95 and 217-224, CupClient 1064-1065 and 1245. sw.js is at v2 with an existing RSC cache. The PendingDraftsBadge path is components/offline/, not layout/.
9. The branch lacks isSessionExpired in lib/sessionAuth.ts, so expired-but-not-closed sessions are not classified by syncEvaluation. Check main/S8-01 and treat expiry as `closed`.
