# Offline and platform

### Offline-First Pattern

- Drafts are keyed by session + user (`cata_session_<sessionId>_user_<userId>`). Connectivity is tracked by `hooks/useConnectivity.ts`; `hooks/useOfflineSync.ts` drains the queue on reconnect.
- Reconnect replay goes through `app/actions/offline.ts`, which keeps the **same authorization as the live path** — Prisma scoped by `cupperId`, never a raw Supabase select, so RLS/ownership rules hold. Conflict rules: no row → create; existing draft → local wins; already submitted → `conflict` unless `force`. `isDraft`/`submittedAt` are never mutated by replay.
- **Write ordering (S8-18)**: evaluation writes may carry an optional `clientTs` (ms epoch of the edit); `lib/evaluationWrite.ts` `writeEvaluationOrdered` (shared by `upsertEvaluation` and the replay core) ignores a strictly older one atomically against `Evaluation.lastClientWriteAt` (rule in `lib/offline/clientWrite.ts`). Absent/invalid `clientTs` = legacy upsert. The column is ordering metadata only: never read it from scoring, the trigger or `AggregateScore`.
- `lib/evaluation.ts` (`computeEvaluationDerived`) computes derived scores for both the live and offline paths so a replayed draft scores identically.
- **Draft status machine (S8-09)**: `lib/offline/status.ts` (pure, tested) owns the transitions: `pending | synced | conflict | failed | closed_unsent | orphaned`. Replay actions (`replayEvaluation/Physical/Extrinsic`) RETURN `synced | conflict | closed | pending | gone | rejected` and never throw for those; `syncEvaluation` keeps its legacy contract but does NOT keep old bundles working across a deploy: Next 16 recomputes server-action ids per build, so a tab left open across a deploy gets "Server Action not found" and shows "pending" until reloaded (drafts stay safe on the device; S8-23 C-06). The hook applies a result only via `applyReplayOutcome(..., { ifUpdatedAt })` so an edit made mid-flight stays `pending`; 5 failed runs park a module as `failed` (manual retry revives it); `closed_unsent`/`orphaned`/`failed` never block the final submit and are listed in the "Notas sin sincronizar" panel (read, copy, confirmed discard, nothing auto-deleted). One module-level lock in `useOfflineSync` means two hook instances never replay at once; replay also runs on resume (`hooks/useResume.ts`). Conflicts are rebuilt from the blobs, never kept only in React state.
- **Sign-out and claim guards (S8-09)**: `UnsyncedGuardProvider` (app layout) exposes `confirmLeave("signOut" | "claim")`; `SignOutButton` and `useGuestClaim` call it. The claim stores the anonymous id in localStorage `cata_claim_anon` when it starts and `ClaimCard` writes the completion marker `cata_claim_done` once `confirmGuestClaim` returns ok (`lib/offline/claimMarker.ts`); the next app mount under that confirming, non-anonymous id runs `rekeyUserBlobs`. `purgeCachesOnUserChange` drops the page/RSC caches when the signed-in id differs from `getLastUser()`.
- `ActionErrorCode` includes the client-only `offline`; `feedback.run` maps a dropped request to it (`isNetworkFailure`). A COMPLETE `closed_unsent` note of a closed group session has "Enviar al organizador" (`submitLateDraft`, S10 WP4b: a draft only, the owner decides); TODO(E5): queued session creation offline.

- **A busy session row during a replay (known behaviour)**: the replay answers `pending` (`app/actions/offline.ts`), `useOfflineSync` maps it to `waiting`, and a waiting module gets no retry timer (`scheduleNext` skips `mod.waiting`). It is retried at the next trigger (resume, reconnect, remount, a new live save). No data is lost and no attempt is burnt.

### PWA / Offline Shell
- `public/sw.js` is a hand-rolled vanilla service worker (no build step, no workbox/serwist). `SW_VERSION` is baked into the cache names (`cata-static-<v>`, `cata-pages-<v>`; currently v5, S8-09/S8-23/S10-WP7: static cache capped at 400 (S8-28; was 120) and least-recently-used (a hit re-puts the entry), `/app/insights`, `/app/profile` and the warm-up exercise pages `/app/warmup/<slug>` (saved reflections) never cached; the `/app/warmup` list may be); **bump it whenever a change would make old cached entries incompatible** (e.g. cache-key logic changes) — `activate` deletes any cache not matching the current version.
- Exclusion rules the fetch handler applies **before** any caching logic — never intercepted: non-GET requests, cross-origin requests (Supabase Realtime `wss://`, etc.), `/api/*` (especially `/api/health` — the 30s connectivity probe in `hooks/useConnectivity.ts` must never be answered from cache), `/auth/*` (magic-link callback must always hit the network), and any path containing `hmr` (dev-only HMR sockets).
- `/_next/static/`, `/_next/image`, `/icons/`, and root-level image assets are cache-first. Navigations and RSC data fetches are network-first with a cache fallback (falling back further to `ignoreSearch` matching, then letting the failure propagate so a route's own error boundary — e.g. `app/[locale]/app/sessions/[id]/cup/error.tsx` — can rebuild from IndexedDB). The `cata-pages` cache is capped at 60 entries (FIFO).
- `components/pwa/ServiceWorkerRegister.tsx` registers the SW **production-only** by default (dev + Turbopack HMR interact badly with a caching layer). To test locally anyway: `localStorage.setItem("cata_sw_dev", "1")` then hard-reload. Mounted once in the root `app/layout.tsx` (the actual HTML shell — not `app/[locale]/layout.tsx`).
- `app/manifest.ts` + `public/icons/icon-{192,512,512-maskable}.png` make the app installable. **The current icons are placeholders** (programmatically generated flat-color + glyph) — swap in real brand icons before shipping broadly.

### Save Status Honesty & Offline Storage
- **Reload notice (S9-01, C-06):** Next 16 recomputes server-action ids per build, so a tab open across a deploy gets `UnrecognizedActionError` ("Server Action … was not found on the server") on every save. `lib/staleBundle.ts` (`isStaleBundleError`, tested) detects it; `flushSave` and the `useOfflineSync` replay latch a module-level flag (`noteIfStaleBundle`) and `StaleBundleNotice` (`components/offline/`, placement rule `lib/staleNoticePlacement.ts`: the app layout copy everywhere except the cup route, where `CupClient` renders it under `OfflineBanner` because the fixed shell covers the layout) shows a persistent, non-blocking "new version, reload" notice with a reload button (`offline.bannerNewVersion` / `offline.reloadNow`). The "device changed user" notice (S10 WP8) is separate: `OfflineBanner` on the cup page (shown first), `IdentityWatcher` bar elsewhere; both stack in normal flow, neither hides the other. Drafts stay on the device and stay `pending` (the replay answers `waiting`, no attempt burned). Only tabs that already run a build with this code can show it.
- `flushSave` in `CupClient` returns `"synced" | "pending"`; the indicator shows an amber **"Guardado en este dispositivo · pendiente de sincronizar"** for `pending` (server write failed or offline) and never auto-clears it — only a later synced flush or `useOfflineSync` reporting `synced` does. The leave-guard swaps to `leaveGuard.bodyPending` while anything is pending. Never map a local-only write to the green "saved" state.
- `lib/offline/store.ts` never rejects: every localforage call is wrapped, the first failure flips `isOfflineStorageUnavailable()` (subscribe with `onOfflineStorageUnavailable`, `useSyncExternalStore`-friendly) and `OfflineBanner` shows `offline.bannerStorageUnavailable`. `PendingDraftsBadge` (app shell) counts pending modules across all sessions so unsynced work is visible outside `/cup`.
- Sign-out goes through `components/layout/SignOutButton.tsx`, which first runs `clearLocalDeviceState()` (`lib/offline/deviceState.ts`: drops the `cata-pages-*`/`cata-rsc-*` SW caches and the last-user pointer, keeps user-keyed drafts) — shared tablets must never serve the previous user's cached pages. Never call `signOut`/`switchAccount` from a plain `<form action>`.

### Platform seam (S8-15)
- `lib/platform/` is the ONLY place for things a Capacitor WebView treats differently from a browser: `env.ts` (`isNativeShell`, `isStandalone`; the only shell sniffing), `files.ts` (`downloadFile` takes a blob, text or URL incl. data URLs; `shareFile`), `print.ts` (`printPage`), `external.ts` (`openExternal`), `openReport.ts` (authenticated fetch then share/save; `offline` without fetching), `inAppBrowser.ts` (UA detection for the login hint), `deepLink.ts` (`routeFromUrl`, pure, via `lib/safeNext.ts`), `storage.ts` (`requestPersistentStorage`, stale-draft rule), `resume.ts` (pure gate behind `hooks/useForegroundResume.ts`). Helpers return `{ ok, via }` and never throw.
- **No raw `window.print`, `window.open`, `createElement("a")` downloads or `window.Capacitor` outside `lib/platform/`** — `tests/platformSeam.test.ts` scans the source and fails. Report links use `components/ui/ReportLink.tsx` (plain anchor on the web, disabled offline, intercepted only in a shell). Every new `/app/*` login redirect carries `?next=`.
- Foreground resume: Cup/Waiting/Results bump a `resumeKey` so the existing realtime effect rebuilds its channel through `subscribeWithSessionAuth`, then refetch (`router.refresh()` / `getWaitingState`). The resume hook re-attaches; it never saves (the `pagehide` flush stays the writer). `useConnectivity()` also returns `recheck()`.
- No Capacitor dependency is installed; native branches are `// TODO(native)` stubs. Device checklist: `docs/native/device-checklist.md`.
