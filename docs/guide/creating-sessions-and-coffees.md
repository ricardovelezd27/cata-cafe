# Creating sessions and coffees

### Auth Pattern

- **Origin data is live and says so (S10 WP5a, F-cafes-9, D1)**: one rule, `originEditedAfterClose` / `sampleOriginEditedAt` (`lib/originEdit.ts`), decides "Datos de origen editados el {fecha}" from the sample's `extrinsic_data.edited_at` or the linked coffee's `Coffee.originEditedAt` (NEVER `updatedAt`) after the moment the session stopped being writable (the earlier of `closedAt` and a passed `closesAt`, `stoppedWritingAt`); `originEditedAt` (migration `20261115090000_coffee_origin_edited_at`, runbook §34) is stamped ONLY by `updateCoffee` and `updateSampleMetadata` when `originFieldsChanged` (`lib/coffeeOrigin.ts`, `COFFEE_ORIGIN_FIELDS`: country, region, farm, producer, species, variety, harvestYear, processType, altitude, roastLevel, certifications) says an origin field changed, never by publish, visibility, invites, claim, anonymize or duplicate; the results drill-down, the CVA PDF and print page (`sheetSampleRecords` -> `originEditedAt`), the stamp of the participant summary and the session ficha, the coffee profile's session list and the coffee ficha PDF all use it. `updateCoffee` requires `expectedUpdatedAt` and writes with ONE `updateMany` guarded by it (atomic; count 0 re-reads to tell `conflict` from `not_found_or_forbidden`); the form shows the reload button.

### Coffee Short Codes
- Every `Coffee` gets a unique 6-char code (`lib/coffeeCode.ts`, alphabet `A-Z2-9` minus lookalikes I/L/O/0/1; displayed hyphenated, e.g. `K7M-3FP`) stamped at every create path: `createCoffee`, the session wizard's `createCoffeesInTx` (inside the session's own transaction since S9-03, so a failed session insert leaves no stray coffee; the whole transaction re-runs via `retryOnCodeCollision`), `updateSampleMetadata`'s implicit create, and `duplicateCoffee`.
- Use `withCodeRetry` (retry-on-P2002) for creates that run as their own implicit transaction. Inside an interactive `$transaction` (e.g. batch wizard creates), pre-generate codes with `generateUniqueCoffeeCodes` and retry the **whole transaction** on collision — a first P2002 aborts the surrounding Postgres transaction (25P02 on every later statement), so a per-row retry can never succeed there (`retryOnCodeCollision` in `lib/coffeeCode.ts` is the helper). `addSessionSample` already takes an optional `coffeeId` (re-validated with `usableCoffeeWhere`); the edit form picks it with `CoffeePicker`.
- `CoffeePicker` ranks code-prefix hits (3+ normalized chars) first but never replaces fuzzy name results; `CoffeesTable` and the coffee detail header show the code as a formatted pill and it is searchable in both raw and hyphenated form.

### Sample / Coffee Metadata Editing
- Session creation and coffee forms only require **name** — altitude is range-checked (1–6000) only when a value is entered, and roast level is optional ("valor antes que fricción": progressive data-quality gate relaxed 2026-09).
- `updateSampleMetadata` merges rather than overwrites: an absent key leaves that coffee field untouched, `""` clears it, and `name` is never blanked. It returns `coffeeUpdated: false` when the linked coffee isn't owned by the caller (the two callers show a dismissible notice instead of failing).
- Cup-page "Usar café existente" (S9-05): for a sample with no coffee the owner's sample editor links an existing coffee through `assignSampleCoffee` (the same `ActionResult` action the results page uses; on an open session it links without revealing). The list is fetched when the picker opens (`listUsableCoffeesForPicker` in `app/actions/coffees.ts`), never shipped in the cup page's props, and only the link is set locally: the coffee's fields come with the server render. `cup/page.tsx` sends `coffeeId` to the owner only; participants get `null`, matching PHASE 21's hidden column. Rule: `canPickExistingCoffee` (`lib/cupCoffeePick.ts`).
- Post-close origin-data editing lives in `ExtrinsicEditDialog` (`components/results/`), opened from the results drill-down for the session **owner** on a **revealed** sample — it reuses `ExtrinsicForm` with its in-cupping header/disclaimer suppressed and still saves through `upsertExtrinsic`.
