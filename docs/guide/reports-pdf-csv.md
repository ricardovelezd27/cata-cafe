# Reports, PDF and CSV

### Auth Pattern

- **Results CSV (S10 WP5a, D5)**: every row has a code `C-XXXX` derived from a KEYED hash of (session id, cupper id) (`csvCupperCodes`, `lib/reports/csvCodeKey.ts`, server-only, secret = the analytics one, domain prefix `results-csv:<sessionId>`; pure `assignCsvCodes`, `lib/reports/csvCodes.ts`, lengthens only colliding codes), so the code reveals neither join order, name order nor the organiser, and differs between sessions. Rows are ordered by sample, then by code, in BOTH variants. `?names=0` (or the old `?codes=1`) is the shareable variant: code only, no name, id or email and NO `motivo_exclusion` column (`excluido` stays).

### CVA PDF Export & Reports (`lib/pdf/`, `lib/reports/`) — see docs/flows.md §6
- **Fonts**: `lib/pdf/fonts.ts` registers Newsreader + Hanken Grotesk (static TTFs in `public/fonts/`, OFL) once; documents use `SERIF`/`SANS` + `fontWeight`, never `Helvetica-*`/`Times-*` literals. `next.config.ts` `outputFileTracingIncludes` ships the TTFs with every PDF-rendering function — a new PDF route must be added there (verify on a Vercel preview). The fonts lack `Σ`/`▼`: draw markers as SVG and localize labels. `sanitizePdfText` (`lib/pdf/text.ts`) strips emoji from user strings. Never set `lineHeight` on a `Page` style — `render()` text (page numbers) disappears.
- **Owner-only data is gated inside the builder**: `buildCvaFormData` requires `ownerView`; physical renders only for the owner, extrinsic for the owner or once `sample.revealed`. Callers (cva-pdf route, close email, print page) also pass gated props — belt and braces. `lib/pdf/cvaFormData.ts` builds the physical block from the real `phys_*` fields plus derived lines (dominant screen "Malla 15 — 42%", Cat.1/Cat.2 full defects via `calcFullDefects`, shared with `PhysicalEvalForm`). Roast level uses the same reveal gate as `coffeeName`.
- **Report models (`lib/reports/`)** are pure and shared with the results page: `ranking.ts` (`rankFor`/`rankSamples`/`sessionStats`/`consensusLine` — the overview calls `rankSamples` through `lib/reports/overview.ts`), `cupperStats.ts` (`rowStats`/`bandFor`, used by `OwnerParticipantSection`), `participantSummary.ts`, `fichaTecnica.ts` (`tier: owner | participant`), `teacherNotes.ts`; `sessionReportData.ts` is the ONE server-only fetch and does NO authz — routes gate first. `canViewGroupResults` (`lib/sessionState.ts`) is the group-visibility rule for page and routes. **Anonymity invariant** (tested): the participant tier never carries another cupper's name/id or physical data.
- **Routes**: `/api/sessions/[id]/participant-summary` (member/owner/super-admin via the owner's lens; 409 while group results are hidden), `/api/sessions/[id]/ficha-tecnica` (owner/super-admin; everyone else 404), `/api/coffees/[id]/ficha` (`usableCoffeeWhere`; community block only if `resultsPublished || owner`), `/api/sessions/[id]/cva-pdf`. All `runtime = "nodejs"`, `force-dynamic`, `maxDuration`, `no-store`, `?inline=1` for the native viewer, filenames via `lib/pdf/filename.ts`. New reports are PDF-only; `PrintClient.tsx` remains the HTML twin of the CVA form only.
- **Charts**: `lib/pdf/charts.tsx` (`PdfRadar`, `PdfPercentBars`, `PdfBarList`, `PdfTrendLine`, `PdfDeviationBand`, `PdfDeltaChip`) over pure `lib/pdf/chartMath.ts`; colours only from `lib/pdf/palette.ts` (the one place hex is sanctioned, mirroring `chartColors.ts`). Preview scripts: `scripts/render-cva-preview.ts`, `render-report-preview.tsx`, `render-participant-summary-preview.tsx`, `render-ficha-preview.tsx` (rasterize with PyMuPDF to inspect).
- **Close email** (`lib/closeEmail.ts`): body links to the results page (login `next=`), attachment = the participant summary only; CVA form attached only with `CLOSE_EMAIL_ATTACH_CVA=1`; group-summary PDF retired. Ledger semantics unchanged.
